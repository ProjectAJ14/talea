```bash
npm install -g @ajaykumarnpm/talea
```

The package name is scoped; the command it installs is just `talea`. (npm's typo-squatting filter refused the bare name `talea` — it called it too similar to `tape`, `taze`, `table` and `jaltea` — so the package wears a scope and the binary does not.)

### Check it landed

```bash
talea --version
talea doctor
```

`talea doctor` is the one that matters. It checks, in order:

| Check | What a failure means |
|---|---|
| **Node.js** | Older than 20. Upgrade before anything else. |
| **git** | Not on `PATH`. |
| **SSH to GitHub** | Your key is not reaching GitHub. Cloning will fail until it does, or until you pass `--protocol https`. |
| **GitHub API** | No token. Not a failure — you get public repos only. |
| **Workspace** | Which tree talea found, and whether this machine has chosen what to keep yet. |

It exits non-zero if something is actually broken, so it is safe to put in a setup script.

### Upgrading

```bash
talea upgrade            # reinstall from npm at the latest version
talea update             # the same thing
talea upgrade --check    # report only, change nothing
```

talea **updates itself automatically**, at most once a day. After a command finishes it checks npm; if a newer version exists, it installs it in the background and writes the output to `~/.talea/update.log`. The command you ran finishes on the old version — talea never changes underneath you mid-run — and the next command prints `Updated 0.7.0 → 0.8.0`, once.

If the background install fails (a global npm folder that needs `sudo`, a proxy that blocks the registry), the next command says so and points at the log. It retries the next day; `talea upgrade` retries now and shows the error.

The background update and the command you typed often run at once, and that is safe: two upgrades never install together — the second, background or typed, stops while the first holds `~/.talea/upgrade.lock` — and `~/.talea/state.json` is written whole and re-read before each change, so neither run loses the other's workspaces, gist or settings. A command started at the very moment npm is replacing talea's files may fail to load; run it again and it loads the new version.

`talea upgrade --off` turns automatic updates and the check off, `--on` turns them back on, and `TALEA_NO_UPDATE_CHECK=1` disables both for a single shell. Every update message goes to stderr, so `$(talea where)` reads a path and nothing else.

:::caution
A copy of talea that is a git checkout refuses to self-upgrade. Replacing somebody's working branch with a release is data loss with a friendly name.
:::

### Teaching your agent to use it

One more command, if you work in Claude Code:

```bash
talea skill install
```

That installs a skill at user scope, so every project you open has it. [For your agent](/docs/agents/) is what it does and what it deliberately refuses to do.
