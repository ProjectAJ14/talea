# Working on `web/`

The site is two halves that share one ground, built by Astro and deployed to
Firebase Hosting at https://talea-run.web.app by `.github/workflows/firebase.yml`.

| Path | What it is |
|---|---|
| `public/index.html` | the landing page — the pitch. Hand-written HTML, copied verbatim into the build; there is no framework in it. |
| `public/styles.css` | landing-page components. |
| `public/tokens.css` | the design tokens: the accent ramp and type scale, then the two grounds. Read by **both** halves. |
| `public/app.js` | landing-page behaviour: the interactive terminal, the scroll reveals, the ground toggle, the star count, the copy buttons. |
| `public/analytics.js` | Firebase Analytics, loaded by both halves from one file so the measurement id cannot drift. |
| `src/content/docs/docs/*.mdx` | the manual, one file per topic. The nesting is what puts them at `/docs/…`. |
| `src/styles/docs.css` | Starlight skinned onto our grounds — it re-points `--sl-color-*` at the roles in `tokens.css`. |
| `src/components/` | two Starlight overrides: our wordmark and the ground toggle. |
| `astro.config.mjs` | the sidebar, which is hand-ordered rather than autogenerated. |

```bash
npm run dev       # localhost:4321, hot reload
npm run build     # -> dist/
npm run preview   # serve dist/ exactly as Firebase will
```

Firebase is the only host, and should stay that way: Astro's `base` is fixed at
build time, so one build cannot serve both a root host and a subfolder host. A
second host means a second build, which drifts.

`firebase.json` sets the cache policy, and the split matters: **HTML is
`no-cache`** (stored, but revalidated on every request) while `/_astro/**` is
immutable for a year. Firebase's default is `max-age=3600` on everything, which
means a fix could ship, deploy green, and still be invisible to a reader for an
hour — their cached HTML points at the previous build's fingerprinted CSS. The
globs are deliberately non-overlapping: header precedence between two matching
`headers` entries is undocumented.

## The design system is shared with eklavya, deliberately

`tokens.css` is the same verdigris ramp, type scale and two grounds that
`eklavya/web` uses, and `styles.css` is its component layer with the parts talea
has no use for removed. **This is one design language across two tools**, and
`src/theme.js` in the CLI carries the same palette as ANSI — the hexes in
`PALETTE` are the `--vd-*` steps in `tokens.css`. Change one and change the
other, or the terminal and the website stop looking like the same product.

What talea does **not** inherit: eklavya's bow-and-arrow flight, the brand-word
rehype plugin, and the tier and dial machinery that is eklavya's subject matter.

**There is no decorative animation on this page and that is deliberate.** A
cutting-takes-root flight was built and then removed: the only moving things
left are the hero terminal, which is the product, and the story loop behind the
WHY copy, which is the argument. Anything that moves and says nothing is noise
on a page about a tool whose whole pitch is that it does less than you fear.

**No brand-word plugin, on purpose.** Eklavya paints every prose mention of its
name in the accent. talea's name is lowercase, it is also the binary, and it is
the subject of nearly every sentence in the manual — accenting all of it would be
accent everywhere and therefore accent nowhere.

## The rule that matters

**The manual is a test of the source, not prose about it.** Every default, flag,
path and command name in it was read out of the code. When you change behaviour,
update the matching page in the same commit — and read the value out of the file
below rather than copying what the page already says, or the page compounds its
own drift.

Every `.mdx` under `src/content/docs/docs/` has a row here, in sidebar order.

## The landing page quotes real output

The hero terminal is not a mock-up. It is a `talea init` run, and every glyph,
colour, row format and count in it comes from the CLI:

| What | Where the real one is built |
|---|---|
| the checkbox picker | `src/prompt.js` — space toggles, arrows walk, enter accepts |
| the glyphs and the spinner frames | `glyph` and `spinner` in `src/theme.js` |
| the group header with its rule and count | `groupHeader()` in `src/log.js` |
| the row: glyph, name, note | `statusLine()` in `src/log.js` |
| the results box and its counts | `summary()` in `src/log.js` |

`RUN` in `app.js` holds the four outcomes a row can settle into. If the CLI gains
a fifth, it belongs there too — a terminal on the landing page that prints
something the tool does not is worse than no terminal.

`styles.css` holds a **no-JS fallback** for the parts JS fills in, in
`.term__screen:not([data-ready]) …::after` rules. The counts there are the ones
the default four ticks produce; change the default ticks and change them too, or
the two disagree silently for exactly the readers who cannot see the
disagreement.

## CSS

- **Name a role, never a scale step or a raw hex.** `--ink`, `--dim`, `--faint`,
  `--line`, `--line-2`, `--panel`, `--mass`, `--spot`, `--spot-ink`. A raw hex or
  a `--vd-*` step in a component pins it to one ground and the theme toggle
  silently stops working for it. The one exception is the terminal, whose palette
  is fixed on both grounds and declared at the top of `styles.css`.
- `scripts/check-css.py` catches the whole class of mistake — it skips the two
  blocks allowed to hold fixed values and reports anything else. Run it from
  `web/`:

```bash
python3 scripts/check-css.py
```

- `.dial__pill` is absolutely positioned in the card's top-right corner, over the
  same line as `.dial__val`. Keep pill labels to **one short word** — "escape
  hatch" collided with its own value and had to become "opt-in".
- `src/styles/docs.css` only re-points Starlight's `--sl-color-*` at our roles.
  Starlight declares its accents inside its own `[data-theme]` blocks, which
  outrank a bare `:root` — so an accent override has to appear in **both** theme
  blocks or it silently loses in one of them.
- Tables: cells use `overflow-wrap: **break-word**`, never `anywhere`. Both break
  a long slug rather than let it push the table, but `anywhere` also shrinks a
  cell's *min-content* to one character — and the key column is `width: 1%` ("as
  narrow as you can be"), so the browser obliges and a table reads
  `S Y M P T O M` down the page.
- Asides come back to our palette: note and tip take `--spot`, caution
  `--warning`, danger `--error`. Starlight's own blue, purple, orange and red are
  four hues that appear nowhere else on this site.
- `public/` assets carry a `?v=N` query. Bump it when you change one, or
  returning readers get the cached copy.
- Grid columns holding code blocks need `minmax(0, 1fr)`, not `1fr` — an `auto`
  track refuses to shrink below the widest `<pre>` and pushes the page sideways.
- Honour `prefers-reduced-motion` in anything animated.

## Before you commit

```bash
npm run build && npm run preview     # localhost:4321
python3 scripts/check-css.py         # no component pins a raw colour
python3 scripts/check-links.py       # every link and anchor in dist/ resolves
```

Then check by hand, every time:

1. **1280, 900 and 560px, in both grounds.** Use the toggle in the nav — a bug
   that only shows on paper is the commonest kind.
2. **No horizontal page scroll** at 560:
   `document.documentElement.scrollWidth === document.documentElement.clientWidth`.
3. **No console errors**, the hero terminal boots, the picker takes arrows and
   space, and the board fills. The docs sidebar marks the current page.

Site-only work is a `docs:` commit — that is what keeps it from cutting a
release. The release workflow runs on every push to `main`; it is the commit
message, not the path, that decides whether a version ships. A `feat:` on a
landing-page headline would publish an npm version of a CLI that did not change.

## Writing conventions for the manual

- **Audience: a developer on their second machine.** They know git. They do not
  know this tool. Explain a talea word the first time it appears — catalogue,
  selection, adopt, park — then use it freely.
- **Say what happens, then why.** The why is one sentence, never a paragraph.
- Sentence case. No emoji. Second person. Present tense.
- **Numbers over adjectives.** "6–12 parallel git operations" beats "a sensible
  number".
- **Never document unshipped work.** `templates/` ships empty and `docs.js` has
  nothing to write, so no page promises group `CLAUDE.md` files.
- Prefer a table when every row has the same shape, `<Steps>` when order matters,
  and prose when neither is true. A two-row table is prose pretending to be data.
- Every command block a reader would paste must be runnable verbatim.
